# 인원 배정 시스템 설계문서 v1

- 상태: 확정
- 버전: 1.0
- 대상: 수강생 및 인사 관리자
- 문서 범위: 서비스 요구사항, 운영 흐름, 화면, 데이터 구조, 기술 방향, MVP 및 완료 기준
- 구현 상태: 본 문서는 설계 기준이며 기능 구현 완료를 의미하지 않는다.

## 1. 서비스 목적

수강생의 역량과 학습 성향을 측정하고, 유사한 수강생을 학습 그룹으로 배정하여 효율적인 교육 운영을 지원한다.

교육 분야를 시스템에 고정하지 않는다. 관리자가 과정마다 분야, 평가 항목, 배점, 가중치 및 채점 기준을 설정한다.

시스템이 그룹 배정안을 제안하고, 관리자가 검토·조정한 뒤 확정하여 수강생에게 공개한다. 자동 배정안은 관리자 승인 없이 공개하지 않는다.

평가 결과는 학습 지원을 목적으로 사용하며, 채용·승진 등 인사평가에 자동 전용하지 않는다.

## 2. 확정된 운영 기준

| 항목 | 기준 |
| --- | --- |
| 제공 형태 | 하나의 웹앱 안에 수강생 영역과 관리자 영역 제공 |
| 기본 진입 화면 | 수강생용 홈 |
| 관리자 진입 | 관리자 로그인 및 `/admin` 영역 |
| 교육 분야 | 관리자가 과정별로 지정 |
| 평가 체계 | 관리자가 평가 항목, 만점, 가중치, 채점 기준 설정 |
| 운영 규모 | 기수당 약 30명 |
| 가입 방식 | 수강생 직접 회원가입 |
| 기수 참여 | 참여 코드 기반 |
| 진단 자료 | 관리자가 작성하여 파일로 첨부 |
| 제출 방식 | 수강생의 텍스트 답안 또는 과제 파일 제출 |
| 채점 방식 | 관리자 수동 채점 |
| 학습 성향 | 공통 학습 선호 설문 |
| 그룹 배정 | 역량 우선, 학습 성향 보조의 유사도 기반 배정 |
| 기본 그룹 규모 | 5명, 최소·최대 인원은 기수별 설정 |
| 배정 확정 | 관리자 검토·조정 후 확정 및 공개 |

기수당 30명이 모두 배정 대상이면 기본적으로 5명씩 6개 그룹을 제안한다. 실제 대상자 수가 다르거나 인원 조건을 충족할 수 없으면 관리자 검토 대상으로 표시한다.

## 3. 사용자와 권한

### 3.1 수강생

- 직접 회원가입 및 로그인
- 참여 코드로 기수 참여
- 진단 안내와 첨부 자료 확인
- 텍스트 답안 또는 과제 제출
- 학습 성향 설문 작성
- 공개된 본인 평가 결과 확인
- 확정·공개된 본인 그룹 확인

회원가입 시 역할은 항상 수강생이다. 가입 화면이나 클라이언트 요청으로 관리자 역할을 선택할 수 없다.

### 3.2 인사 관리자

- 담당 과정과 기수 생성·관리
- 교육 분야 및 평가 기준 설정
- 참여 코드 발급·비활성화
- 수강생 참여 현황 관리
- 진단 자료 등록
- 제출물 확인 및 항목별 채점
- 결과 분석과 배정안 생성
- 그룹 수동 조정
- 배정 확정 및 공개
- 변경 이력 확인

관리자는 담당 과정과 기수의 정보에만 접근한다. 관리자 권한은 별도의 통제된 절차로 부여하며, 공개 회원가입으로 생성하지 않는다.

### 3.3 계정 및 세션 원칙

- 수강생 영역과 관리자 영역은 공통 디자인을 사용하되 권한은 서버에서 구분한다.
- 관리자 메뉴를 숨기는 것만으로 접근 통제를 구현하지 않는다.
- 모든 조회·수정·다운로드 요청에서 역할, 기수 참여 여부 및 담당 범위를 검증한다.
- 공용 기기에서 다른 사람이 이용하려면 로그아웃 후 해당 계정으로 로그인한다.
- 관리자에게 짧은 유휴 세션 만료 및 중요 작업 재인증을 적용한다.
- 운영 환경의 관리자 계정에는 다중 인증을 권장한다.
- 관리자 수강생 화면 미리보기는 실제 수강생으로 제출하는 기능과 구분한다.
- 같은 계정으로 여러 과정에 참여할 수 있지만 결과와 권한은 과정·기수별로 분리한다.

## 4. 과정과 기수

### 4.1 과정

과정은 교육 분야와 교육 목적을 정의하는 단위다.

주요 정보:

- 과정명
- 교육 분야
- 과정 설명
- 학습 목표
- 담당 관리자

### 4.2 기수

기수는 특정 과정의 모집, 진단, 채점 및 그룹 배정을 운영하는 단위다.

주요 정보:

- 소속 과정
- 기수명
- 목표 모집 인원
- 모집 기간
- 진단 시작일 및 마감일
- 참여 코드
- 평가 기준 버전
- 그룹 목표·최소·최대 인원
- 결과 및 배정 공개 상태

동일한 과정을 여러 기수로 운영할 수 있다. 다른 기수의 결과와 배정 상태를 혼합하지 않는다.

### 4.3 참여 코드

- 로그인한 수강생이 유효한 참여 코드를 입력하면 해당 기수에 참여한다.
- 동일 계정의 동일 기수 중복 참여를 방지한다.
- 참여 코드에는 유효 기간 및 비활성화 기능을 제공한다.
- 코드 입력 요청에는 시도 횟수 제한 등 추측 공격 방어를 적용한다.
- 참여 코드는 관리자 권한을 부여하지 않는다.
- 모집 종료 또는 참여 제한 시 신규 참여를 차단한다.

참여 신청 후 관리자 승인 방식은 향후 확장으로 남기며, MVP의 기본 참여 방식은 참여 코드다.

## 5. 핵심 이용 흐름

### 5.1 관리자

1. 관리자 로그인
2. 과정 및 기수 생성
3. 교육 분야와 평가 항목 설정
4. 진단 자료 및 제출 안내 등록
5. 설정 검증 후 모집·진단 공개
6. 수강생 참여 및 제출 현황 확인
7. 항목별 채점 완료
8. 그룹 조건 설정 및 배정안 생성
9. 배정 근거와 인원 조건 검토
10. 필요 시 수동 조정 및 변경 사유 기록
11. 배정 확정 및 공개

### 5.2 수강생

1. 회원가입 및 로그인
2. 개인정보 처리 안내 확인 및 필요한 동의
3. 참여 코드로 기수 참여
4. 진단 자료 및 제출 안내 확인
5. 답안 또는 과제 제출
6. 학습 성향 설문 제출
7. 관리자 공개 후 본인 평가 결과 확인
8. 확정·공개된 그룹 및 학습 목표 확인

### 5.3 상태 관리

운영 단계는 다음과 같이 구분한다.

- 기수: 준비 → 모집·진단 운영 → 채점 → 배정 검토 → 공개 → 종료
- 제출: 미작성 → 임시 저장 → 제출 완료
- 채점: 미채점 → 채점 중 → 채점 완료
- 배정 실행: 생성 중 → 검토 대기 → 확정
- 결과 공개: 비공개 → 공개

구체적인 상태 전이와 재제출 허용 정책은 상세 구현 설계에서 정의하되, 미완료 결과의 배정 반영 및 미확정 배정의 공개를 금지한다.

## 6. 평가 체계

### 6.1 평가 항목 설정

관리자는 과정의 목적에 맞게 평가 항목을 추가한다.

각 항목에는 다음 정보를 저장한다.

- 항목명
- 측정 목적 및 설명
- 만점
- 가중치
- 채점 기준
- 필수 여부
- 그룹 배정 반영 여부

특정 분야의 평가 항목을 코드에 고정하지 않는다.

### 6.2 설정 검증

- 만점은 0보다 커야 한다.
- 점수는 0 이상 만점 이하여야 한다.
- 종합 점수 산정 대상 항목의 가중치 합계는 100%여야 한다.
- 배정에 사용하는 항목의 가중치는 해당 항목 집합 안에서 정규화한다.
- 배정 반영 항목과 유효한 가중치가 없으면 배정안 생성을 차단한다.
- 필수 항목 미채점 상태는 0점과 구분한다.
- 필수 채점이 완료되지 않은 수강생은 배정 대상에서 보류한다.

### 6.3 점수 계산

항목별 원점수는 다음과 같이 0~100점으로 환산한다.

항목 환산 점수 = 원점수 ÷ 항목 만점 × 100

종합 점수는 환산 점수의 가중 평균으로 산출한다.

그룹 배정은 종합 점수만 사용하지 않고 항목별 점수 구성을 비교한다. 종합 점수가 같더라도 강점과 보완 영역이 다르면 다른 그룹에 배정될 수 있다.

서로 다른 과정의 점수와 등급은 동일한 척도라고 가정하지 않는다.

### 6.4 학습 단계

- 등급은 우열이 아닌 현재 학습 단계를 나타낸다.
- 관리자가 과정에 맞는 단계명과 점수 구간을 설정한다.
- 구간의 중복 및 누락을 검증한다.
- 단계 기준은 평가 기준 버전에 포함한다.
- 초기 기준은 운영 가설이며 실제 학습 성과를 확인하며 보정한다.
- 단계명이나 점수 구간 변경으로 과거 결과를 조용히 재해석하지 않는다.

### 6.5 평가 기준 버전

- 평가 항목, 배점, 가중치, 채점 기준 및 학습 단계 기준을 버전으로 관리한다.
- 진단 개시 후 기존 기준의 임의 수정을 제한한다.
- 변경이 필요한 경우 새 버전과 변경 사유를 기록한다.
- 응시 및 평가 결과에 적용된 버전을 보존한다.
- 같은 배정 실행에서는 비교 가능한 평가 기준을 적용한 결과를 사용한다.

## 7. 첨부형 진단과 제출

### 7.1 기본 원칙

진단 자료 첨부와 점수 산출은 별개 기능으로 구현한다.

첨부 파일에서 문항, 정답 또는 평가 기준을 자동으로 추출한다고 가정하지 않는다. 평가 항목과 채점 기준은 관리자가 웹 화면에서 별도로 설정한다.

### 7.2 관리자 첨부

- 진단 자료 업로드
- 제출 방식과 제출 안내 입력
- 제출 마감 설정
- 적용 자료 버전 관리

초기 허용 형식은 PDF, DOCX, XLSX를 중심으로 한다. 허용 형식 및 용량 상한은 서버 설정으로 관리하며, 운영 배포 전에 확정한다.

### 7.3 수강생 제출

- 텍스트 답안 또는 허용된 과제 파일 제출
- 임시 저장
- 최종 제출 확인
- 제출 시각 및 상태 기록

재제출 허용 여부와 마감 후 제출 정책은 기수 운영 정책으로 명시한다. 기존 제출물을 변경하는 경우 이력을 보존한다.

### 7.4 채점

- 관리자가 제출물과 채점 기준을 확인한다.
- 수강생별·항목별 점수를 입력한다.
- 피드백을 작성한다.
- 필수 항목 입력 및 점수 범위 검증 후 채점을 완료한다.
- 점수 변경 시 채점자, 변경 시각 및 사유를 기록한다.
- 보조 기능으로 점수 CSV 일괄 등록을 제공한다.
- CSV 등록은 기수별 수강생 식별자, 항목 식별자, 중복 및 점수 범위를 검증한 뒤 반영한다.

AI 서술형 자동 채점과 첨부 문서 자동 문항 추출은 MVP에서 제외한다.

### 7.5 파일 보호

- 첨부 파일과 제출물은 비공개 저장소에 보관한다.
- 진단 자료는 해당 기수 참여자와 담당 관리자만 접근한다.
- 제출물은 제출자 본인과 담당 관리자만 접근한다.
- 다운로드 요청에서도 권한을 검증한다.
- 확장자, 실제 파일 유형 및 용량을 서버에서 검증한다.
- 실행 파일은 허용하지 않는다.
- 사용자 파일명은 저장 경로나 접근 권한의 근거로 사용하지 않는다.
- 자료가 변경되면 기존 파일을 조용히 덮어쓰지 않고 적용 버전을 보존한다.

## 8. 학습 성향 설문

학습 성향은 심리 진단이나 고정적인 성격 분류가 아니라 현재의 학습 선호도다.

공통 설문 축:

- 개념 설명 중심 ↔ 실습 중심
- 개인 학습 중심 ↔ 협업 중심
- 단계별 안내 선호 ↔ 자율 탐색 선호
- 반복 학습 선호 ↔ 빠른 진도 선호

설문에는 우열을 매기지 않는다. 응답을 공통 척도로 환산하고 설문 버전 및 산출 기준을 기록한다.

성별, 나이 등 학습 목적과 직접 관련 없는 개인정보는 군집화 변수에서 제외한다.

MVP의 배정 대상은 필수 평가 및 학습 성향 설문을 완료한 수강생이다. 설문 미완료는 임의의 기본값으로 대체하지 않고 보류 사유로 표시한다.

## 9. 그룹 배정

### 9.1 배정 원칙

- 같은 기수 안에서 배정한다.
- 역량 유사도를 우선한다.
- 학습 성향 유사도는 보조 기준으로 사용한다.
- 인원 제한을 반영한다.
- 관리자에게 배정 근거를 제공한다.
- 최종 확정은 관리자가 수행한다.

학습 성향이 유사하다는 이유만으로 역량 차이가 큰 수강생을 우선 배정하지 않는다.

### 9.2 배정 절차

1. 참여 상태, 필수 평가 및 설문 완료 여부로 대상자를 선별한다.
2. 동일한 평가 기준과 유효한 점수인지 검증한다.
3. 평가 항목별 점수를 0~100점으로 환산한다.
4. 배정 반영 항목과 가중치로 역량 유사도를 계산한다.
5. 역량이 유사한 후보 사이에서 학습 성향 유사도를 반영한다.
6. 목표·최소·최대 인원을 고려해 그룹 배정안을 생성한다.
7. 보류 대상과 조건 위반을 별도 표시한다.
8. 관리자가 검토·조정한다.
9. 중복 배정 및 인원 조건을 재검증한다.
10. 관리자가 확정하고 공개한다.

### 9.3 초기 알고리즘 방향

기수당 약 30명 규모에서는 모델 학습보다 설명 가능한 규칙 및 유사도 기반 배정을 사용한다.

배정 엔진은 항목별 역량 유사도, 학습 성향 유사도 및 그룹 인원 제약을 함께 처리한다. 단순히 종합 점수 순으로 인원을 자르거나 일반 군집화 결과를 그대로 확정하지 않는다.

구체적인 거리 함수, 역량 우선 처리 방식, 동점 처리 및 인원 조정 절차는 구현 전 상세 알고리즘 명세로 정의하고 테스트한다.

배정 실행에는 다음을 기록한다.

- 대상자 및 사용한 결과 버전
- 평가 기준과 설문 버전
- 그룹 인원 조건
- 알고리즘 버전 및 적용 설정
- 생성 시각과 실행자
- 생성 결과 및 보류 사유

### 9.4 인원 제약 및 예외

- 기본 목표 인원은 그룹당 5명이다.
- 최소·최대 인원은 관리자가 기수별로 설정한다.
- 대상자 수와 제약이 맞지 않으면 무리하게 배정하지 않는다.
- 미응시, 미제출, 미채점, 설문 미완료는 각각 구분해 표시한다.
- 한 수강생은 동일한 확정 배정에서 하나의 그룹에만 속한다.
- 보류 대상은 사유와 함께 별도 목록으로 제공한다.
- 인원 조건을 만족하지 못하면 조건 조정 또는 명시적인 관리자 예외 승인을 요구한다.

### 9.5 관리자 조정 및 공개

관리자는 그룹별 구성원, 인원, 역량 분포 및 배정 근거를 확인한다.

수동 이동 시 인원 조건 위반과 역량 분포 변화를 보여준다. 변경 사유 및 변경 전후 상태를 기록한다.

확정 이후 재배정은 기존 결과를 덮어쓰지 않고 새 배정 이력으로 관리한다. 공개 중인 배정을 명확히 구분한다.

수강생에게는 본인 그룹명, 학습 목표, 일정 및 공개가 허용된 구성원 정보만 제공한다. 다른 수강생의 점수, 등급 및 설문 원문은 공개하지 않는다.

## 12. 기술 구성

신규 구현의 기본 기술 방향은 다음과 같다.

| 구분 | 구성 |
| --- | --- |
| 웹 프레임워크 | Next.js + TypeScript |
| UI | Tailwind CSS 및 공통 컴포넌트 |
| 데이터베이스 | PostgreSQL |
| 데이터 접근 | Prisma |
| 인증 | 검증된 인증 라이브러리 또는 관리형 인증 서비스 |
| 파일 | 비공개 객체 저장소 |
| 초기 배정 엔진 | 서버 측 TypeScript |

초기에는 하나의 애플리케이션으로 구성한다. 인증 제품, 배포 환경 및 저장소 공급자는 구현 착수 시 선정한다.

군집화 고도화가 필요하면 Python 분석 작업 분리를 검토한다. 초기 구현에는 별도 분석 서버나 모델 학습 인프라를 요구하지 않는다.

구체적인 라이브러리 버전, API 계약 및 배포 구성은 상세 구현 설계에서 확정한다.

## 13. 보안 및 개인정보

- 모든 데이터 접근은 서버에서 인증·인가한다.
- 세션 쿠키에는 HttpOnly, Secure 및 적절한 SameSite 설정을 적용한다.
- 상태 변경 요청에는 CSRF 등 웹 공격 방어를 적용한다.
- 로그인·회원가입·참여 코드 입력에는 요청 제한을 적용한다.
- 비밀번호 저장과 세션 관리는 검증된 인증 기능을 사용한다.
- API 키, 데이터베이스 접속 정보 및 비밀 값은 환경 변수로 관리한다.
- 공개 회원가입으로 관리자 권한을 부여하지 않는다.
- 수강생별 결과 및 제출물은 다른 수강생에게 노출하지 않는다.
- 개인정보 수집 목적, 보유 기간, 삭제 및 탈퇴 정책을 운영 전에 명시한다.
- 결과 다운로드와 관리자 변경을 감사 로그에 남긴다.
- 평가 결과를 학습 지원 목적 이외로 사용하려면 별도의 정책 및 적법한 절차를 검토한다.

## 16. 완료 기준

### 계정 및 권한

- 가입 요청으로 관리자 역할을 획득할 수 없다.
- 미참여자는 해당 기수의 진단 자료와 결과에 접근할 수 없다.
- 수강생은 다른 수강생의 제출물·점수·설문에 접근할 수 없다.
- 관리자는 담당 범위 밖 과정에 접근할 수 없다.
- 로그아웃하거나 세션이 만료되면 관리자 접근이 차단된다.

### 평가 및 파일

- 만점, 점수 범위 및 가중치 오류를 차단한다.
- 필수 미채점과 0점을 구분한다.
- 허용하지 않은 파일과 용량 초과 업로드를 차단한다.
- 파일 다운로드에도 접근 권한이 적용된다.
- 평가 기준 및 자료 변경 이력이 보존된다.
- CSV 오류는 반영 전에 확인할 수 있다.

### 그룹 배정

- 같은 기수의 유효한 완료 결과만 사용한다.
- 30명·목표 5명 조건에서 6개 그룹을 생성할 수 있다.
- 나누어떨어지지 않는 인원과 불가능한 인원 조건을 처리한다.
- 중복 배정을 방지한다.
- 보류 대상과 보류 사유를 표시한다.
- 배정 근거 및 적용 알고리즘 버전을 확인할 수 있다.
- 수동 변경과 예외 승인 이력이 남는다.
- 확정·공개 전 배정안이 수강생에게 노출되지 않는다.
- 재배정 시 이전 이력이 보존된다.
