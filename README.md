# HRsys

수강생 진단 결과와 학습 선호를 바탕으로 학습 그룹을 제안하고, 관리자가 검토·확정하여 공개하는 웹 애플리케이션입니다.

설계 기준은 `docs/design-v1.md`입니다.

## 구현 상태

현재 버전은 **핵심 운영 흐름을 실행할 수 있는 1차 MVP**입니다.

전체 설계 범위가 구현되었거나 운영 배포 준비가 완료된 상태는 아닙니다. 실제 개인정보 대신 가상 데이터로 로컬 검증하세요.

### 구현한 기능

- 수강생 직접 회원가입 및 이메일·비밀번호 로그인
- 공개 회원가입에서 관리자 역할 생성 차단
- 통제된 CLI를 통한 최초 관리자 생성
- 서버 측 인증 및 관리자 담당 과정 접근 제어
- 과정과 첫 기수 동시 생성
- 참여 코드 기반 기수 참여 및 중복 참여 방지
- 참여 코드 만료·비활성화
- 과정별 평가 항목, 만점, 가중치, 채점 기준 및 학습 단계 설정
- 생성 시 평가 기준 v1 고정 및 결과의 적용 버전 기록
- 텍스트 답안 임시 저장 및 최종 제출
- 4개 축 학습 선호 설문
- 관리자 수동 채점, 피드백, 점수 변경 이력
- 항목별 점수 평균·최저·최고 조회
- 필수 채점 및 설문 미완료 대상 보류
- 항목별 역량 우선·학습 선호 보조의 결정적 그룹 배정
- 그룹 목표·최소·최대 인원 검증
- 관리자 수동 이동 및 변경 사유 기록
- 입력 결과 버전 재검증 후 배정 확정 및 공개
- 공개된 본인 결과와 본인 그룹 조회
- 재배정 시 이전 확정 결과와 현재 공개 결과 분리
- 중요 작업 비밀번호 재인증
- 로그인·가입·참여 코드·재인증 요청 제한

### 아직 구현하지 않은 기능

다음 항목은 설계문서의 MVP 범위에 포함되지만 이 1차 구현에는 포함되지 않습니다.

- 비공개 객체 저장소 연동
- 진단 자료 및 과제 파일 업로드·다운로드와 파일 형식 검증
- 진단 자료 버전 관리
- 점수 CSV 일괄 등록 및 반영 전 미리보기
- 기존 과정에 추가 기수 생성하는 UI
- 평가 기준 개정·새 버전 발행 UI
- 평가 기준의 일반 폼 편집 UI: 현재는 검증되는 JSON 입력 사용
- 설문 단독 임시 저장: 현재 답안 임시 저장·제출과 함께 저장
- 인원 제약을 위반하는 관리자 예외 승인
- 전체 감사 로그 검색·페이지네이션
- 이메일 확인, 계정 복구, MFA
- 실제 개인정보 처리방침, 탈퇴·삭제·익명화 정책
- 운영 배포, 백업 및 복구 자동화
- 통합·브라우저 E2E 및 부하 테스트

따라서 `docs/design-v1.md`의 전체 완료 기준을 충족했다고 간주하지 않습니다.

## 기술 구성

- Next.js App Router 및 TypeScript
- React
- Tailwind CSS
- PostgreSQL
- Prisma
- NextAuth.js Credentials 기반 JWT 세션
- bcryptjs
- Zod
- Vitest

NextAuth.js가 세션과 로그인 CSRF 처리를 담당하고, 회원가입 및 업무 변경은 Next.js Server Actions로 처리합니다. 사용자 역할과 담당 범위는 서버에서 데이터베이스를 조회하여 확인합니다.

의존성 설치 후 생성한 `package-lock.json`을 검토하여 별도 커밋하고, 배포 전 보안 업데이트를 확인하세요. 현재 변경안에는 실행 환경에서 생성하지 않은 lockfile을 임의로 포함하지 않았습니다.

## 로컬 실행

권장 환경:

- Node.js 22 LTS
- npm
- Docker 및 Docker Compose

1. `.env.example`을 `.env`로 복사합니다.
2. `NEXTAUTH_SECRET`에 충분히 긴 무작위 값을 설정합니다.
3. PostgreSQL을 시작합니다: `docker compose up -d`.
4. 패키지를 설치합니다: `npm install`.
5. 초기 마이그레이션을 생성·적용합니다: `npm run db:migrate -- --name init`.
6. 개발 서버를 실행합니다: `npm run dev`.
7. 브라우저에서 `http://localhost:3000`에 접속합니다.

`.env.example`과 Docker Compose의 데이터베이스 계정은 로컬 개발용 예시입니다. 실제 운영 비밀번호로 재사용하지 마세요.

비밀 값은 저장소에 커밋하지 않습니다.

### 최초 관리자 생성

`.env`에 다음 값을 설정합니다.

- `ADMIN_EMAIL`: 관리자 이메일
- `ADMIN_NAME`: 관리자 이름
- `ADMIN_PASSWORD`: 12자 이상이며 UTF-8 기준 72바이트 이하인 비밀번호

실행 명령은 `npm run admin:create`입니다.

`tsx` 실행 시 환경 변수를 직접 주입하거나, Node.js 22의 env-file 옵션을 사용하여 `node --env-file=.env --import tsx scripts/create-admin.ts`로 실행합니다.

기존 계정이 존재하면 이 스크립트는 실패하며, 기존 수강생 계정을 관리자로 승격시키지 않습니다.

생성 이후 `ADMIN_PASSWORD` 환경 변수는 제거하세요.

### 마이그레이션 관리

최초 실행으로 생성되는 `prisma/migrations` 디렉터리를 검토하고 저장소에 커밋해야 합니다.

운영 배포에서는 검토된 마이그레이션을 대상으로 `npm run db:deploy`를 사용합니다. 운영 환경에서 `prisma migrate dev` 또는 검토되지 않은 `db push`를 실행하지 마세요.

## 사용 흐름

### 관리자

1. 관리자 계정으로 로그인합니다.
2. 관리자 대시보드에서 과정·첫 기수를 생성합니다.
3. 교육 분야, 진단 안내, 평가 항목 및 그룹 인원을 지정합니다.
4. 기수 상세에서 참여 코드를 확인하여 전달합니다.
5. 수강생 답안이 모이면 사유와 비밀번호를 입력하여 채점을 시작합니다.
6. 제출 답안을 확인하고 항목별 점수·피드백을 저장합니다.
7. 배정안을 생성하고 보류 대상과 그룹별 역량 범위를 확인합니다.
8. 필요하면 구성원을 수동 이동하고 변경 사유를 남깁니다.
9. 사유와 비밀번호를 입력하여 배정안을 확정·공개합니다.

### 수강생

1. 가상 정보로 회원가입하고 로그인합니다.
2. 참여 코드로 기수에 참여합니다.
3. 진단 안내와 평가 기준을 확인합니다.
4. 텍스트 답안과 학습 선호 설문을 임시 저장합니다.
5. 최종 제출합니다.
6. 관리자 공개 이후 본인 평가 결과와 그룹을 확인합니다.

다른 수강생의 점수, 설문 원문 및 제출물은 수강생 화면에 제공하지 않습니다.

## 1차 MVP 운영 정책

### 일정

- 모집·진단은 기수 생성 즉시 시작합니다.
- 모집 종료와 제출 마감은 UTC 기준 ISO 8601 문자열로 입력합니다.
- 모집 종료 이전에만 신규 참여할 수 있습니다.
- 제출 마감 이전에만 답안을 저장·제출할 수 있습니다.
- 관리자가 채점을 시작하면 마감 전이라도 참여와 제출이 종료됩니다.
- 운영 종료는 공개된 기수에 대해서만 허용합니다.

### 제출과 설문

- 텍스트 답안만 지원합니다.
- 답안과 4개 설문 축을 함께 저장합니다.
- 임시 저장 시에도 4개 설문 응답이 필요합니다.
- 최종 제출 후 재제출 및 마감 후 제출은 허용하지 않습니다.
- 최종 제출된 답안은 덮어쓰지 않습니다.
- 설문 버전은 1입니다.
- 각 축은 1~5의 동일 척도를 사용합니다.
- 설문 미완료를 임의의 중립값으로 대체하지 않습니다.

### 평가

- 항목은 교육 분야와 무관하게 관리자가 설정합니다.
- 항목 ID는 영문 소문자로 시작하며 영문 소문자, 숫자, 밑줄만 허용합니다.
- 전체 항목 가중치 합계는 100이어야 합니다.
- 필수 항목 점수는 누락할 수 없습니다.
- 0점은 유효한 점수이며 미채점과 다릅니다.
- 선택 항목이지만 종합 점수 가중치가 양수인 항목이 미채점이면 종합 점수는 보류합니다.
- 양수 가중치를 가진 배정 반영 항목이 미채점이면 그룹 배정을 보류합니다.
- 학습 단계 구간은 하한 포함·상한 미포함입니다.
- 마지막 학습 단계 구간은 100점을 포함합니다.
- 평가 기준은 기수 생성 시 고정하며 개정 기능은 아직 없습니다.
- 점수 변경은 채점·배정 검토 단계에서만 허용합니다.
- 공개 후 점수를 수정하는 기능은 아직 없습니다.

### 배정 알고리즘

알고리즘 식별자는 `capacity-nearest-profile/1`입니다.

1. 제출·필수 채점·설문·버전을 검증하여 대상자를 추립니다.
2. 배정 반영 항목의 점수를 각각 0~100점으로 환산합니다.
3. 해당 항목의 가중치를 배정 반영 항목 집합 안에서 정규화합니다.
4. 최소·최대 인원을 만족하는 그룹 수 중 평균 인원이 목표에 가장 가까운 값을 선택합니다.
5. 인원 차이가 최대 1명이 되도록 그룹별 정원을 먼저 결정합니다.
6. 참여 식별자로 정렬한 대상자의 첫 번째 사람을 시드로 사용합니다.
7. 현재 그룹의 항목별 중심과 가중 제곱 역량 거리가 가장 가까운 사람을 선택합니다.
8. 역량 거리가 소수점 6자리 기준으로 같을 때만 학습 선호 거리를 비교합니다.
9. 두 거리도 같으면 참여 식별자로 결정합니다.
10. 모든 그룹 정원을 채우고 중복·누락·인원 조건을 검증합니다.

따라서 총점 순으로 단순 분할하지 않으며 학습 선호 때문에 역량 거리가 더 큰 후보를 먼저 배정하지 않습니다.

30명, 목표 5명, 최소 3명, 최대 6명이면 5명씩 6개 그룹을 생성합니다.

이 방식은 설명 가능한 초기 탐욕 알고리즘이며 전역 최적 배정을 보장하지 않습니다. 실제 교육 데이터로 시드 편향, 역량 분포 및 학습 성과를 검증해야 합니다.

실행마다 다음을 보존합니다.

- 평가 기준 및 설문 버전
- 배정 반영 점수와 설문 입력
- 사용한 결과 버전
- 인원 조건
- 알고리즘 버전
- 실행자, 생성 시각 및 사유
- 그룹 구성과 보류 사유

### 조정과 공개

- 검토 중에는 수동 이동을 위해 일시적으로 인원 조건을 위반할 수 있습니다.
- 이동 후 그룹별 항목 점수 범위를 다시 표시합니다.
- 확정 시에는 모든 대상자가 정확히 한 그룹에 포함되어야 합니다.
- 확정 시 인원 조건을 위반하면 차단합니다.
- 배정 생성 이후 점수가 변경되면 기존 안은 확정할 수 없습니다.
- 보류 대상이 있으면 관리자가 확인해야 공개할 수 있습니다.
- 확정과 공개는 하나의 트랜잭션에서 수행합니다.
- 현재 버전은 평가 결과와 그룹을 함께 공개합니다.
- 새 검토안 생성만으로 현재 공개 중인 결과를 바꾸지 않습니다.
- 확정된 안은 변경하지 않으며 재배정은 새로운 실행으로 생성합니다.
- 수강생에게는 본인 그룹명과 과정 학습 목표만 제공합니다.
- 구성원 개인정보와 그룹 일정 관리 UI는 아직 제공하지 않습니다.

## 보안과 동시성

- 데이터 변경은 서버에서 사용자 역할과 기수 참여·담당 범위를 확인합니다.
- 관리자 역할은 세션의 클라이언트 값이 아니라 데이터베이스에서 확인합니다.
- 관리자 접근은 로그인 후 최대 15분으로 제한합니다.
- 이는 유휴 시간보다 더 엄격한 절대 만료 정책이며 활동 여부와 관계없이 재로그인이 필요합니다.
- 일반 수강생 세션의 최대 유효 기간은 8시간입니다.
- 코드 비활성화, 채점 시작, 기수 종료 및 배정 공개는 비밀번호 재인증이 필요합니다.
- 비밀번호 해시는 bcrypt 비용 12를 사용합니다.
- bcrypt 입력 잘림을 방지하기 위해 UTF-8 기준 72바이트를 초과하는 비밀번호는 거부합니다.
- 업무 변경은 기수 행의 PostgreSQL 행 잠금을 통해 직렬화합니다.
- 채점은 결과 버전 비교로 오래된 화면의 덮어쓰기를 차단합니다.
- 배정 확정은 생성 당시 스냅샷과 최신 입력을 비교합니다.
- 요청 제한 카운터는 PostgreSQL upsert의 원자적 증가를 사용합니다.
- 제한 키의 이메일 등 식별자는 SHA-256 해시로 저장합니다.
- 만료된 RateLimit 행은 주기적 작업으로 삭제해야 합니다.
- 감사 로그에는 점수·피드백 변경 전후가 포함되므로 운영 환경에서 접근 권한 및 보존 정책이 필요합니다.
- 기본 세션 쿠키 보안 속성은 NextAuth.js에 위임합니다. 운영 환경은 반드시 HTTPS와 올바른 NEXTAUTH_URL을 사용하세요.
- 프록시 배포 시 Server Actions의 Origin/Host 검사 설정을 검증하세요.

- 평가 가중치와 학습 단계 범위 검증
- 0점과 필수 미채점 구분
- 점수 범위 및 가중 평균
- 설문 미완료 등 보류 사유
- 30명·목표 5명 배정
- 나누어떨어지지 않는 인원 처리
- 불가능한 인원 조건 차단
- 동일 입력의 결정적 배정
- 총점이 같아도 다른 항목별 역량 구분
- 학습 선호의 보조 우선순위
- 중복 배정 검증

인증·담당 범위·트랜잭션 동시성·브라우저 흐름 테스트는 후속으로 추가해야 합니다.
